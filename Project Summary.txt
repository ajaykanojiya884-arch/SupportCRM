Datastraw Operations CRM Dashboard

Executive summary:
Datastraw Operations is a full-stack customer support and operations management application. It is designed for internal support teams that need one place to receive customer cases, track progress, review workload, and maintain a clear history of operational activity.

Business problem addressed:
Support teams often manage customer issues across email, spreadsheets, and disconnected tools. This project demonstrates how those activities can be organized into a centralized workflow with authenticated access, structured ticket records, status tracking, search, reporting, and a responsive web interface.

What the application does:
- Allows team members to request a one-time verification code by email and sign in securely.
- Provides a dashboard showing ticket totals, open work, tickets in progress, closed tickets, and recent activity.
- Lets users create support tickets with customer details, subject, description, and contact information.
- Provides ticket search, status filtering, pagination, detailed views, and update history.
- Supports operational statuses including Open, In Progress, and Closed.
- Allows support staff to add investigation notes and customer follow-up information to tickets.
- Provides analytics for recent ticket volume and resolution activity.
- Uses protected API routes so ticket and analytics data require an authenticated session.
- Includes responsive layouts for desktop and mobile workflows.

Typical user workflow:
1. A support team member opens the portal and enters their email address.
2. The system sends a one-time verification code through the configured email service.
3. After verification, the user enters the operations dashboard.
4. The user reviews workload metrics and recent tickets.
5. The user creates, searches, opens, or updates a ticket.
6. The user changes the ticket status and records notes as the issue progresses.
7. The analytics view provides a high-level view of operational performance.

Technical implementation:
- Frontend: React, TypeScript, Vite, Tailwind CSS, and React Router.
- Backend: Python, FastAPI, Pydantic, SQLAlchemy, and Alembic.
- Database integration: SQLite for local development and MySQL-compatible configuration for production.
- Authentication: Email OTP verification with hashed verification codes and hashed session tokens.
- API design: REST-style FastAPI endpoints under the /api path.
- Deployment: Vercel Services configuration for a Vite frontend and FastAPI backend in one project.
- Repository structure: A monorepo with separate frontend and backend service roots.

How to run locally:
1. Open a terminal in the backend folder.
2. Activate the virtual environment:
   D:\mini\.venv\Scripts\Activate.ps1
3. Start the FastAPI backend:
   cd D:\mini\backend
   python -m uvicorn app.main:app --reload --port 8000
4. Open a second terminal in the frontend folder.
5. Install frontend dependencies and start Vite:
   cd D:\mini\frontend
   npm install
   npm run dev
6. Open the local frontend URL shown by Vite in a browser.
